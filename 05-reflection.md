## Exercise 6: return to the doubt

> **Required personalization:** the original Module 1 response was not provided. The following is a working assumption and must be replaced with the learner's actual doubt before submission.

### Assumed original doubt

“I am not convinced that agent architecture, rather than better conventional workflow automation and management, is the main explanation for the productivity gap.”

### Has my view changed?

Yes, but only partly. The intervening modules make a strong case that shared context, explicit actor identity, and accountable execution are necessary when software participates in knowledge work. This scenario shows why: 91% classifier accuracy is useless without an exception path, three retrieval systems increase fragmentation, and Copilot speed does not move a constrained release system. Role architecture is valuable because it forces permissions, handoffs, memory, verification, and responsibility to be explicit.

### Strongest remaining objection

Those principles are not uniquely “agent” principles. A well-run rules engine, case-management workflow, integration service, or human team also needs context, identity, controls, and measurement. Calling the design agentic can encourage unnecessary model use where deterministic software is cheaper and easier to validate. The thesis is strongest as an operating model for mixed human/software work, and weaker if it implies that agents are the source of the gain.

### Evidence that would settle it

Run matched workflow pilots with the same baseline, staffing, governance change, and measurement: one using conventional automation/search and one adding bounded agents for unstructured evidence work. Compare within-30-day completion, verified defects, exception/rework rate, staff minutes, engineering/support hours, unit cost, and audit-replay success over enough cases and time to cover meaningful exceptions. Evidence that the agent-enabled path produces a durable net improvement beyond the governance/workflow redesign—and survives handoff to the client—would change the objection. If both perform similarly, the redesign and controls, not agent architecture, deserve the credit.
